# 라이브 방송 운영 절차서

WOLF에서 잭앤질 대회를 온라인 생중계할 때 쓰는 문서입니다.
현장에서 급할 때는 [1페이지 요약본](./live-broadcast-1page.md)만 보셔도 됩니다.

---

## 0. 전체 그림

```
스마트폰 4대 ──SRT(현장 와이파이)──> 현장 노트북 OBS ──RTMP──> YouTube Live ──> WOLF
   각 앵글 촬영                        씬 4개 중 1개만 송출              시청자
                                             ↑
                                     영상감독이 앵글 선택
                                             ↑
                                     WOLF 스위처 콘솔
```

**4대가 동시에 나가는 게 아니라, 매 순간 1개 앵글만 유튜브로 나갑니다.**
어느 앵글을 내보낼지 고르는 것이 영상감독의 일이고, WOLF는 그 선택을 담당하는 콘솔을 제공합니다.

WOLF가 하는 일은 여기까지입니다. 영상 자체는 WOLF 서버에 오지 않습니다 —
인코딩·합성·송출은 전부 OBS와 유튜브가 합니다.

### 두 가지 운영 모드

| | 모드 A — 지시 | 모드 B — 브리지 |
|---|---|---|
| 감독이 클릭하면 | 탈리 화면에 번호가 뜬다 | OBS 씬이 자동으로 바뀐다 |
| 오퍼레이터 | 그 번호 씬을 직접 누른다 | 지켜본다 |
| 준비물 | 인터넷만 | 노트북에 브리지 스크립트 설치 |
| 실패하면 | 방송에 영향 없음 | 모드 A로 내리면 됨 |

**첫 행사는 모드 A로 하세요.** 모드 B는 리허설에서 한 번 돌려 본 뒤에 씁니다.

---

## 1. 사전 준비 (행사 전날까지)

### 1-1. OBS 씬 4개 만들기

앵글마다 씬을 하나씩 만들고 이름을 정합니다. 예:

| 씬 이름 | 앵글 |
|---|---|
| `Main` | 메인무대 |
| `Floor` | 플로어 |
| `Judges` | 심사석 |
| `Wide` | 와이드 |

> 이름은 짧게, 헷갈리지 않게. 나중에 WOLF에 **똑같이** 입력해야 합니다.

### 1-2. 유튜브 라이브 만들기

1. 유튜브 스튜디오 → 만들기 → 실시간 스트리밍 시작
2. 공개 범위를 **공개** 또는 **일부공개**로 둡니다. (비공개는 임베드가 안 돼 WOLF에서 재생되지 않습니다)
3. OBS에 스트림 키를 넣고 송출을 겁니다.
4. 주소창의 주소를 복사해 둡니다.

### 1-3. WOLF에 방송 등록

어드민 → **라이브 방송관리** → 추가

| 항목 | 넣는 값 |
|---|---|
| 연결 행사 | 해당 페스티벌(행사패스) — 연결하면 행사 페이지에 LIVE 버튼이 뜹니다 |
| 방송 제목 | 한/영 |
| URL 슬러그 | 제목에서 자동 생성됩니다. `jlcf-2026-final` 처럼 |
| 유튜브 주소 | 복사한 주소를 그대로 붙여넣습니다 |
| 백업 HLS | 있으면 넣고, 없으면 비웁니다 |
| 방송 예정 시각 | 예정 화면의 카운트다운에 쓰입니다 |
| 채팅 노출 | 보통 켭니다 |

**유튜브 주소를 넣으면 바로 아래에 미리보기가 뜹니다. 이 영상이 맞는지 눈으로 꼭 확인하세요.**
엉뚱한 영상을 걸고 방송을 시작하는 것이 가장 흔한 사고입니다.

저장한 뒤 같은 화면에서 **카메라 1~4번**을 채웁니다.

| 번호 | 이름 | OBS 씬 이름 | 담당자 | 프리뷰 주소 |
|---|---|---|---|---|
| 1 | 메인무대 | `Main` | 홍길동 | (선택) |
| 2 | 플로어 | `Floor` | … | (선택) |

#### 프리뷰 주소 — 스위처 안에서 4앵글을 보고 싶을 때만

넣으면 스위처 카드에 그 앵글 화면이 깔립니다. **비워 두면 그 칸만 회색으로 남고, 전환·탈리·브리지는
지금과 똑같이 동작합니다.** 방송 자체와는 무관한 부가 기능입니다.

주의할 점이 하나 있습니다. **폰 → OBS 는 SRT 라서 브라우저가 재생하지 못하고, 그 영상은 WOLF 서버로
오지도 않습니다.** 그래서 프리뷰를 보려면 앵글마다 **웹에서 열리는 주소가 따로 하나씩** 있어야 합니다.
넣을 수 있는 것:

| 넣는 것 | 어떻게 만드나 | 지연 |
|---|---|---|
| 앵글별 유튜브 라이브 주소 | 앵글마다 유튜브 라이브를 따로 열고 폰이 그쪽으로도 송출 | 10~30초 |
| HLS 주소 (`.m3u8`) | 미디어 서버(SRS·MediaMTX 등)가 SRT 를 받아 HLS 로 다시 뿌림 | 5~20초 |
| 카메라 스냅샷 주소 (`.jpg`) | IP 카메라·미디어 서버의 스냅샷 주소 — 2초마다 새로 받습니다 | 2초 |
| MJPEG 주소 | IP 카메라의 MJPEG 스트림 | 1초 안팎 |

> **프리뷰는 실제 송출 화면이 아닙니다.** 지연이 있어 "지금 무대에서 무슨 일이 일어나는가"를 이 화면으로
> 판단하면 늦습니다. 앵글 구도를 확인하는 용도로만 쓰고, 정밀 확인은 여전히 OBS 멀티뷰로 하세요.
> 앵글별 유튜브 라이브는 폰 업링크가 2배로 들어갑니다. 회선이 빠듯하면 넣지 마세요.

> **OBS 씬 이름은 대소문자·공백까지 정확히 같아야 합니다.** `Main`과 `main`은 다른 씬입니다.
> 브리지를 한 번 실행하면 OBS의 실제 씬 목록이 드롭다운으로 나오므로 골라 넣으면 안전합니다.

### 1-4. 현장 화면 두 개 열어 두기

방송 편집 화면 아래 **현장 링크**에서:

- **스위처 콘솔** — 영상감독이 보는 화면. 감독의 노트북/태블릿에서 엽니다.
- **탈리 화면** — OBS 오퍼레이터가 보는 화면. 현장 노트북에서 전체화면으로 띄웁니다.
  로그인 없이 열리는 주소라 **현장 노트북에만** 전달하세요.

### 1-5. (모드 B만) 브리지 설치

[tools/obs-bridge/README.md](../tools/obs-bridge/README.md) 참고. 리허설에서 한 번 돌려 보세요.

## 2. 당일 운영

### 2-1. 시작

1. OBS 송출을 겁니다. 유튜브 스튜디오에서 화면이 들어오는지 확인합니다.
2. 탈리 화면을 현장 노트북에 전체화면으로 띄웁니다. (F11)
3. 감독은 스위처 콘솔을 엽니다. 옆에 OBS 멀티뷰를 함께 띄워 놓습니다.
   - 카메라에 **프리뷰 주소**를 넣어 뒀다면 스위처 카드에 그 앵글이 깔립니다. 지연이 있는 참고 화면이라
     정밀 확인은 OBS 멀티뷰로 합니다.
   - 프리뷰 주소를 안 넣었다면 스위처에는 영상이 나오지 않습니다. 폰 영상이 WOLF 서버로 오지 않기
     때문이며, 이는 업링크를 아끼는 이 구성의 대가입니다. 이때 앵글 확인은 전적으로 OBS 멀티뷰로 합니다.
4. 어드민에서 **방송 시작**을 누릅니다. → 시청자 화면이 플레이어로 바뀝니다.

### 2-2. 앵글 전환

스위처에서 카메라를 클릭하거나 단축키를 씁니다.

| 키 | 동작 |
|---|---|
| `1` `2` `3` `4` | 그 번호 앵글로 전환 |
| `Space` | 직전 앵글로 되돌리기 (두 앵글을 오갈 때) |
| `?` | 단축키 도움말 |

- **클릭하면 즉시 나갑니다. 확인 창은 없고, 되돌리기도 없습니다.**
- 입력칸(공지·진행 순서)에 커서가 있으면 단축키가 동작하지 않습니다. 의도된 동작입니다.
- 같은 앵글이 90초를 넘으면 버튼에 은은한 표시가 뜹니다. 강제는 아니고 알림입니다.

### 2-3. 진행 순서와 공지

- **현재 순서**에 `예선 3조` 처럼 적어 두면 전환 기록에 함께 남습니다.
  나중에 "결승은 몇 번 카메라로 나갔나"를 되짚을 수 있습니다. `다음 순서` 버튼은 끝 숫자를 1 올립니다.
- **공지**는 시청자 화면 상단 배너로 뜹니다. 자주 쓰는 문구는 버튼 한 번으로 나갑니다.

### 2-4. 종료

1. 어드민에서 **방송 종료** → 시청자 화면이 종료 안내로 바뀝니다.
2. 유튜브 다시보기가 준비되면 **다시보기 공개**를 누릅니다. 같은 주소가 다시보기 페이지가 됩니다.
3. 스위처에서 **CSV**를 눌러 전환 기록을 내려받아 보관합니다. VOD 챕터·클립 추출의 기준 자료입니다.

## 3. 장애 대응

### 브리지가 끊겼다 (모드 B)

스위처 상단에 `브리지: 끊김`이 뜹니다.

1. 스위처 상단 드롭다운에서 **모드 A**로 바꿉니다. → 즉시 탈리 지시 방식으로 돌아갑니다.
2. 오퍼레이터에게 "이제 탈리 보고 수동으로 바꿔 주세요"라고 알립니다.
3. 여유가 생기면 브리지 창을 다시 실행합니다. OBS가 켜져 있으면 알아서 다시 붙습니다.

**브리지 복구를 방송보다 우선하지 마세요.** 모드 A로도 방송은 완전히 굴러갑니다.

### 카메라 1대가 죽었다

1. 스위처에서 그 카메라의 **끊김**을 누릅니다. → 선택이 막혀 실수로 나가지 않습니다.
2. 그 카메라가 지금 나가고 있었다면 화면 위에 크게 경고가 뜹니다. 다른 앵글로 바로 바꾸세요.
3. 복구되면 **정상**을 눌러 되돌립니다.

### 유튜브가 막혔다 / 재생이 안 된다

1. 어드민 → 해당 방송 → **영상 소스**를 `백업 (HLS)`로 바꾸고 저장합니다.
2. 시청자 화면이 백업 영상으로 바뀝니다. **이때 채팅은 자동으로 숨겨집니다.**
3. 백업 주소가 없으면 공지로 상황을 알리고(`기술적 문제로 잠시 중단`), 유튜브 복구를 기다립니다.

### 시청자 화면이 안 바뀐다

시청자 화면은 실시간으로 따라오고, 실시간이 막힌 망에서도 30초 안에 폴링으로 따라옵니다.
1분 넘게 그대로면 새로고침을 안내하고, 어드민에서 상태가 실제로 저장됐는지 확인하세요.

### 유튜브 채팅이 빈칸이다

`NEXT_PUBLIC_EMBED_DOMAIN` 환경변수가 실제 접속 도메인과 다릅니다.
(운영은 `www.worldoflatinfestivals.com`) 개발자에게 알려 주세요.

## 4. 이번 범위에 없는 것

- **티켓 소지자만 시청** — 유튜브는 임베드 가능한 영상이 공개·일부공개뿐이라 게이팅이 원천적으로 불가능합니다. 나중에 Cloudflare Stream으로 옮길 때 다룹니다.
- **폰 영상을 WOLF 로 직접 받기** — 폰은 OBS 로만 보냅니다. 스위처 프리뷰는 앵글마다 따로 등록한
  '프리뷰 주소'를 재생하는 것이지, 송출 신호를 받아 보여 주는 것이 아닙니다.
- **촬영자 개인 탈리** — 폰이 송출 중이면 다른 앱을 띄울 수 없습니다. 무전기나 별도 기기로 전달하세요.
- 시청자 수 집계, 점수 오버레이 연동, 자동 VOD 아카이빙.
