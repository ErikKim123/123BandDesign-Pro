# 타이틀 태그 작성 규칙 (SEO Title Policy)

검색결과에 노출되는 `<title>` 의 작성·생성 규칙. 구현 단일 소스는 [`packages/shared/src/seo.ts`](../../../packages/shared/src/seo.ts) 의 `buildEventTitle()` 이며,
web(메타 생성)·admin/partner(작성 미리보기)가 모두 이 함수를 쓴다. **문서와 코드가 어긋나면 코드가 기준.**

## 1. 형식

```
[행사명] [유형] [연도] [의도어] — [도시, 국가] | [일정] | [브랜드]
```

| 예시 | |
|---|---|
| EN | `MBF Melbourne Bachata Festival 2026 Tickets — Australia` |
| KO | `MBF 멜버른 바차타 페스티벌 2026 티켓 — 호주 \| WOLF` |

| 슬롯 | 값 | 출처 |
|---|---|---|
| 행사명 | 수동 SEO 제목 > 상품명 | `event_content.seo.title` → `products.name_i18n` |
| 유형 | Festival / Congress / Workshop / Bootcamp / Party / Social / Competition | `event_content.eventType` |
| 연도 | 시작일의 연도 | `event_content.startAt` |
| 의도어 | Tickets / 티켓 / チケット / 門票 | 티켓 상품에만 |
| 도시 | `address.city` → `address.province` → 주소 첫 조각 (숫자 섞인 값은 제외 — `B1`·`64 Dawson St`) | `event_content.address` |
| 국가 | ISO2 → 로케일 표시명 (한국어는 통칭: AU=호주) | `event_content.country` |
| 일정 | `Oct 2–4` / `10월 2~4일` | `startAt`·`endAt` |
| 브랜드 | `WOLF` | 고정 |

## 2. 원칙

1. **왼쪽 우선.** 검색 매칭에 가장 중요한 고유명(행사명)이 항상 맨 앞, 브랜드는 맨 뒤.
   왼쪽에서 잘려나가는 일이 없어야 한다.
2. **구매 의도어를 반드시 넣는다.** `"melbourne bachata festival tickets"` 류 검색어는 의도어가 없으면 매칭되지 않는다.
3. **로컬 시그널(도시/국가)을 넣는다.** 지역 검색(`"bachata festival melbourne"`)을 잡는 축.
4. **중복 금지.** 행사명에 이미 있는 연도·유형·도시·국가·의도어는 다시 붙이지 않는다.
   (예: 이름이 "…Bachata Festival 2026" 이면 `Festival`·`2026` 을 다시 붙이지 않는다.)
5. **표기 언어를 섞지 않는다.** 한글 제목에 영문 도시명(`Bangkok`)을 끼워 넣지 않는다 —
   한글 도시명이 없으면 국가명(로케일 변환값)으로 대체한다.
6. **베뉴(호텔/스튜디오)명은 도시가 아니다.** 지역 검색어가 아니므로 위치 슬롯에 쓰지 않는다.
7. **페이지마다 고유해야 한다.** 목록/상세가 같은 제목을 갖지 않게 한다.

## 3. 길이 예산과 생략 순서

* 예산: **표시폭 60** (한글·CJK 는 1글자 = 2폭 → 영문 60자 / 한글 30자). 구글은 ≈600px 에서 자른다.
* 링크 공유(OG/트위터)용 제목은 별도로 **88폭**까지 허용하고 브랜드를 유지한다.
* 예산을 넘으면 아래 순서로 **뒤쪽 신호부터** 자동 생략한다 (검색노출 기여도가 낮은 것부터).

```
일정 → 브랜드 → 국가 → 도시 → 부제(수동 꼬리말) → 유형 → 의도어
```

브랜드(`| WOLF`)를 국가보다 먼저 버리는 이유: 도메인 권위가 아직 낮아 브랜드 토큰의 클릭 기여가
지역 키워드보다 작다. 브랜드는 OG 제목에서 항상 유지되므로 공유 맥락에서는 손실이 없다.

**되살리기(re-add).** 덩치 큰 항목(부제 등)을 덜어내 예산이 남으면 가치 높은 순으로 다시 넣는다.
이게 없으면 `Latin Bangkok Fiesta 2026 Festival Tickets`(42폭)처럼 18폭이 남는데도 국가가 빠진다.

**말줄임(…)은 쓰지 않는다.** 다 덜어내도 예산을 넘으면(=행사명 자체가 긴 경우) 자르지 않고 그대로 둔다.
잘라내면 뒤쪽 키워드가 **색인에서도** 사라지지만, 그냥 두면 구글은 표시할 때만 자르고 색인은 전체를 한다.
대신 어드민 미리보기에서 빨간색으로 경고해 사람이 줄이도록 유도한다.

## 3-1. 수동 제목 분해 규칙

수동 제목은 통째로 쓰지 않고 아래처럼 쪼개, 예산이 모자랄 때 **핵심어(의도어)가 마지막까지 남게** 한다.

| 입력 | base | 떼어낸 꼬리말 |
|---|---|---|
| `Saigon Latin Festival 2026 – Dec 3-7 \| Vung Tau, Vietnam` | `Saigon Latin Festival 2026` | `Dec 3-7`(일정) · `Vung Tau, Vietnam` |
| `Latin Bangkok Fiesta 2026 – 20th Anniversary Latin Dance Festival` | `Latin Bangkok Fiesta 2026` | `20th Anniversary…`(부제) |
| `PSLF 2026 – Phu Quoc Summer Latin Festival` | (분해 안 함) | — |

* `|` 뒤는 항상 꼬리말.
* 대시(`–`, `—`, ` - `) 뒤는 **일정이거나**, 대시 앞이 이미 완결된 이름일 때(18폭 이상 + 3단어 이상)만 꼬리말로 본다.
  `PSLF 2026 – …` 처럼 앞이 약칭뿐이면 뒤가 진짜 행사명이므로 건드리지 않는다.
* 유형어·연도·도시·국가의 중복 판정은 **그때 남아있는 문구 기준**으로 매번 다시 한다.
  부제를 덜어내면 그 안에 있던 `Festival`·`2026` 이 사라지므로 다시 붙여야 하기 때문이다.

## 4. 수동 입력(오거나이저/어드민) 취급

* `SEO 제목`을 입력하면 그 문구를 **base 로 존중**하고, 빠진 신호(의도어·도시·국가 등)만 보충한다.
* 수동 입력의 `|` 뒤 꼬리말(예: `… | Oct 2–4`)은 **일정 슬롯**으로 인식해 중복 생성하지 않고,
  길이 초과 시 일정과 같은 우선순위로 생략된다.
* 비워두면 전 슬롯이 자동 생성된다. **대부분의 경우 비워두는 편이 낫다.**
* 어드민·파트너 위저드의 SEO 단계에 실제 노출될 제목이 EN/KO 로 미리보기된다.
  폭 표시가 빨간색이면 **예산 초과** 또는 **핵심어(Tickets/티켓) 누락**이므로 제목을 줄인다.
  수동 제목이 60폭에 가까우면 의도어가 들어갈 자리가 없어진다 — 행사명만 남기는 편이 낫다.

## 5. 작성 시 하지 말 것

* 키워드 나열 (`바차타, 살사, 키좀바, 페스티벌, 티켓, 2026 …`) — 스팸으로 평가된다.
* 모든 행사에 같은 접두어 (`[WOLF] …`) — 왼쪽 자리를 낭비한다.
* 이모지·HTML 엔티티 — 잘림 계산이 어긋나고 깨져 노출될 수 있다.
* 60폭을 넘기는 수동 제목 — 뒤가 잘려 의도어가 사라진다.
